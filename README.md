# 星联体·天巡灾情实时预报系统

面向自有卫星任务规划的全球自然灾害事件发现 MVP。系统聚合公开权威事件源，仅保留具备遥感观测价值的灾种，并按照无锡市、江苏省、中国、全球四级重点范围生成观测优先级。

本系统定位为“事件发现、证据聚合与 AOI 核对后的任务候选生成”演示系统，不承担无人值守告警下发或值班研判。FIRMS 热异常、GloFAS 洪水预测及代表性区域坐标会明确降级标注；只有来源几何可靠或经操作员确认的 AOI 才能进入仿真与导出流程。

## 当前能力

- 接入应急管理部地质灾害快报、USGS 与 EMSC 地震、USGS Ground Failure 震生滑坡概率、NVE Jordskredvarsling 官方区域预警、NASA EONET、GDACS、NOAA NHC 与 NWS Alerts、加拿大 ECCC GeoMet、日本气象厅 JMA、Copernicus EMS Rapid Mapping、USGS HANS、Smithsonian GVP 与 NASA LHASA。
- 应急管理部通报只有在正文明确给出发生时间、灾种和受影响地时才进入“实况”，同一灾害后续通报聚合为一个主事件；官方地名经高德编码并近似归一到 WGS84，始终按代表点要求人工核对 AOI。跨境灾害分别保存起源国家和受影响国家。
- USGS Ground Failure 仅把黄色及以上模型产品作为“预报”并强制复核；NVE 使用 Kartverket 官方市县 Polygon/MultiPolygon 恢复预警适用区；NASA LHASA 读取带批次时间的免认证灰度风险图，实时地图仍只产出官方24小时有效期内不低于80%的高风险区。评测链路会把原始概率PNG及其校验值、尺寸和概率直方图另行归档，低风险格不会进入实时事件列表。
- 第一优先级的 NASA FIRMS、WMO SWIC/CAP、Copernicus GloFAS，以及第二优先级的 OCHA ReliefWeb 已有独立连接器；需要密钥或订阅地址的源会明确显示“待配置”，配置字段见 `.env.example`。
- 中国气象数据网 CMA 支持两条独立链路：带几何的 CAP/GeoJSON 预警流，以及 `SURF_CHN_MUL_HOR_3H` 地面站核验流。后者按官方目录约滞后2天、每日更新，仅作为独立核验数据读取；在没有预警编号、流域或台风编号等确定关联键时，不自动并入灾害、不单独创建任务，也不会替换权威事件中心和等级。
- 免密钥的 MET Norway Locationforecast 为全球默认逐小时天气底座；配置 QWeather 后优先使用其格点预报，失败或额度耗尽时自动回退。二者均按事件或任务 AOI 查询未来72小时云量、降水、风速和光学气象窗口，采用30分钟服务端缓存，且不改变灾害等级，也不把数值模式结果冒充站点实况或官方预警。
- 统一地震、火灾、洪水、气旋、火山、滑坡、泥石流、干旱等事件模型；泥石流作为滑坡/地表物质运动父类下的独立子类型，拥有更短的24小时黄金观测期和跨境影响字段。
- 将不同来源的同一物理事件按灾种时空阈值合并为主事件，并保留来源证据链、可信度和事件生命周期。
- 对有编号或名称的持续过程建立灾害实体键：同一台风、编号洪水、火山活动和季度干旱只显示一个主事件；同源连续通报作为“更新历史”，不同来源才计为独立证据。
- 标注精确点位、估算点位、区域代表点和未知位置；非精确坐标必须由操作员核对 AOI 后才能进入任务候选单。
- 标记直接可观测、灾后可观测和条件可观测事件。
- 自动生成观测目标和任务优先级；综合分由严重度、重点范围、遥感适用性、时效和证据可信度共同构成，低可信度事件会被显式扣分。
- 支持“综合优先”“最新发生”和“最近更新”三种排序，避免持续更新过程与真正新发生事件混为一谈。
- 按灾种和现象阶段划分黄金观测期、后续观测期、强制复核点与历史库；预报/预警以权威有效期为硬上限，实况只允许上游实质活动时间续期，缓存读取时间不能续期。
- 短时数据源不再报告某事件时，系统会从 D1 延续该主事件并标为“来源暂未复现”，直至观测期届满或权威撤销，避免把 Feed 滚动窗口误当成灾害结束。
- 管理员可在“系统评测中心”录入带权威依据、时空容差和检测时限的历史核验样本，并执行30/90/365天回放。系统把“已发生事件检测”与“滑坡/泥石流事前预测”分开统计；后者支持真实事件和同口径无事件对照、50%–100%阈值扫描、精确率、误报率、Brier分数与概率可靠性。至少具备5个事件和5个无事件对照才给出探索性阈值建议，且仍要求按区域/季节分组并用独立留出样本复验。原始概率PNG在Sites写入R2，在VPS写入`TIANXUN_FORECAST_ARCHIVE_DIR`，数据库只保存可检索元数据。
- 评测中心可由管理员按需建立首批20条 NASA Global Landslide Catalog 正样本试验库。服务端只接受2000—2020年、降雨类诱因、HTTPS原始来源和 exact/1 km/5 km 定位精度记录，并按13条 `landslide`、5条 `mudslide`、2条 `debris_flow` 确定性抽样，同一国家最多2条；同一原始报道，以及同日同国相距25 km以内的近邻记录不会重复入选。严格条件下官方目录只有2条 `debris_flow` 合格记录，因此不为凑数放宽标准。所有记录强制以草稿导入，保留目录记录号、原始链接、定位精度和日期级时间占位说明；不得自动标记已核验，也不得把目录空白区自动当作无事件对照。该试验库需要另行接入LHASA v1历史栅格后才能执行模型回放。
- 支持全球地图、灾种筛选、地区搜索与四级重点范围。
- 台风事件显示官方逐时中心路径、象限风圈和不确定区组成的 4D 影响场，并严格区分路径概率锥/70%预报圆与风圈影响范围；逐时时间片只在官方节点之间插值，不越过本报次有效期，也不使用自行外推替代官方报次。
- 台风来源 AOI 的卫星机会按每次过境时刻匹配对应逐时预测片，可分别跟踪预测中心、风圈或路径不确定区；选择机会后地图自动聚焦该拍摄时刻的未来目标，并在任务地图保留完整 4D 路径时间轴，可逐时查看中心、风圈和不确定区或一键返回拍摄时刻。时间轴浏览不会修改已选机会。机会保存官方报次、提前时效和预测中心，官方新报次或目标策略变化会使旧机会失效并要求重算。
- 事件详情按需反向解析中文地点，同时保留权威来源原文用于核对。
- 可将事件加入独立卫星任务侧栏；站点部署使用 Cloudflare D1，VPS 后台使用 SQLite，本机缓存仅作离线回退；候选项直接显示灾害发生时间，可编辑成像时间窗，并从完整载荷清单中多选。
- AOI 支持点、圆、矩形、走廊、地图手绘 Polygon/MultiPolygon、GeoJSON 上传与最多多块离散目标；自交、世界级范围和超量顶点会在前后端共同拒绝。
- 任务 AOI、完整事件状态和任务版本由服务端绑定并以 SHA-256 生成指纹；并发修改、权威报次更新、来源几何变化或观测期结束后必须重新核对，不能拿旧任务静默导出。
- 服务端可生成带包 ID、快照校验和、WGS84 AOI、来源证据、版本号、逐时台风影响切片与约束条件的 JSON、CSV 和 GeoJSON 仿真输入包；该包明确不代表已排程或已下发。
- 任务按已认证用户隔离；操作员只可维护候选/已复核状态，排程、下发、成像和产品完成状态预留给带机会、轨道和外部回执的执行适配器。每个任务 revision 都保存操作者、状态和不可变审计快照。
- 提供 `/api/visibility` 两级仿真接口：未配置外部服务时使用当前 TLE/SGP4 生成轨道近接候选，显示最近距离、升降轨和地图搜索圈，并明确其不代表 SAR 可成像；有已登记的天仪 SAR 参数时生成假设传感器机会。台风任务使用逐时移动 AOI，未声明支持移动 AOI 的外部仿真接口会被拒绝，避免输出伪静态跟踪结果。修改 AOI、时间窗、载荷、轨向或台风跟踪目标会自动作废旧机会，轨道级粗筛与假设传感器结果不得直接排程或下发。
- 可见性响应同时生成版本化的 `tianxun.planning.problem/v1` 规划问题、规划汇总和逐机会约束评估；覆盖率、分辨率、入射角、轨向、台风预测片及工程约束均使用稳定原因码区分“可试排、待核验、拒绝”，并预留 `tianxun.planning.schedule/v1` 排程输出，避免把提示文案误当成机器约束或把试算机会直接下发。
- 候选任务面板可把已计算的规划问题送入 `/api/planning/schedule`，比较“优先级贪心基线”和“有界约束搜索”。求解器处理同星时间冲突、临时转换缓冲、优先级、时效、覆盖质量和重访次数；服务端会重算机会约束并校验规划内容指纹。试排结果不改变任务状态，也不自动下发；真实姿态机动、功耗、存储、热控和下传参数未接入前会持续显示为假设。
- 规划工作台提供按卫星分行的甘特时间轴，以及机会锁定、排除、指定卫星和指定成像模式等人工硬约束。操作员可把当前结果保存成账号隔离、带校验和的不可变 D1/SQLite 版本，恢复到同一批规划问题、对比两个版本并导出 JSON；历史版本只保存仿真证据，不会改写任务状态或伪装成执行指令。
- 任务执行器可通过 `/api/execution/receipts` 写入版本化回执，原子推进排程、下发、成像、完成、失败和撤回结果，并与任务 revision、外部任务号和不可变审计记录绑定。只有 `executor` 或管理员凭据可写，重复回执 ID 仅在内容一致时幂等返回。
- 成像成果通过 `/api/products` 登记为 STAC 1.0 Item，保存任务、主事件、平台、载荷、产品级别、质检状态、WGS84 几何、bbox 和 HTTPS asset。产品目录只管理元数据，不把远端资产伪装成本地文件，也不在任务尚未成像时提前登记。
- 任务 AOI 可按真实/标称场景宽度生成最多 200 个复核分块，支持领取、提交、独立复核、退回修改和批准；领取人与复核人必须是不同账号，所有转换都带 revision 与审计快照。网格是覆盖复核单元，不冒充精确多边形裁剪结果。
- 影响风险模型升级为分灾种插件式初筛：地震优先使用矩震级、台风优先使用官方预报最大持续风速，其余灾种在缺少定量强度时明确退回官方等级代理。结果同时显示危险性区间、分数区间和待补输入，禁止把初筛分当作损失预测。
- 数据源异常时独立降级，并在全部源不可用时显示演示数据。
- 事件详情可按当前 AOI 查询 WorldPop 指定年份人口模型；超过匿名接口 50,000 km² 单次上限的 AOI 会自动裁剪为安全分块，保留已完成任务并在重试时续算，汇总后再生成基础暴露度指数。OpenStreetMap Overpass 用于筛查已映射建筑、道路和医疗/应急/避难/教育/电力/供排水设施；AOI 与设施点会叠加到地图，结果按事件版本和 AOI 指纹持久化缓存。道路桥隧查询也写入共享 OSM 查询缓存，服务重启后仍可复用，并在上游短时失败时明确标记为过期缓存降级。
- 暴露度结果不等同于实时人口、设施存量或受损评估：WorldPop 年份、空间分辨率、查询范围、OSM 数据时点、查询时间和缓存状态会随结果保存；OSM 零记录不会被解释为现实中不存在，也不会自动降低人口暴露度指数。默认公共 Overpass 的任务总量上限为 10,000 km²，任务按不超过 750 km² 的非重叠几何分块受控续算，建筑、道路与设施均按 OSM 类型和 ID 跨块去重；标准 30 km 地震筛查圆通常拆为 4 块。配置独立的 `china_daily` 中国日更镜像后可按运维设定扩大到最高 100,000 km²，但仍禁止把全国建筑和道路作为一次全量查询。高德 POI 可补充中国境内关键设施位置，不能替代建筑、道路存量统计或道路实时通行状态。
- 中国 OSM 数据服务器的部署边界、日更切换和应用配置见 [`vps/osm-china/README.md`](vps/osm-china/README.md)。江苏范围另提供轻量本地索引试点：建筑和道路按约 1 km 网格代表点预汇总，关键设施保留可定位点位；AOI 位于江苏或与江苏相交时无需公共 Overpass 分块，跨省 AOI 只统计与江苏覆盖区的交集并明确标注范围，完全不相交时才回退全球流程。部署与科学口径见 [`vps/osm-jiangsu/README.md`](vps/osm-jiangsu/README.md)。

## 本地运行

需要 Node.js 22.13 或更高版本。

```bash
npm install
npm run dev
```

访问 `http://localhost:3000`。

运行前将 `.env.example` 复制为 `.env.local`，填入获批的数据源和仿真服务配置。数据库使用 `.openai/hosting.json` 中的 `DB` 绑定；本地开发会自动初始化并迁移 `drizzle/` 中声明的表结构。

CMA 地面观测默认使用无锡 58354、宜兴 58346、江阴 58351、苏州 58349 四站；仓库内的官方站点索引可校验并支持任意1至30个订购站号。真实账号和密码只能写入未被 Git 跟踪的 `.env.local` 或 VPS `/etc/tianxun/engine.env`。官方文档给出的旧接口会把账号密码放在明文 HTTP 查询串中，因此系统默认拒绝调用；生产环境应优先配置 `CMA_SURFACE_API_URL` 为 HTTPS 凭据转发网关。只有明确接受明文传输风险时，才可将 `CMA_SURFACE_ALLOW_INSECURE_HTTP` 设为 `true`。

全球天气默认直接调用无需密钥的 MET Norway Locationforecast，并使用可配置的识别性 `MET_WEATHER_USER_AGENT`。如需更高分辨率增强，可在和风天气控制台创建免费项目，将专属 API Host 和 API KEY 写入 `QWEATHER_API_HOST`、`QWEATHER_API_KEY`；凭据只由 `/api/weather` 服务端代理读取。系统也支持 Ed25519 JWT。QWeather 默认最多引入120个新坐标/日，任一提供方的同一0.01°格点结果均缓存30分钟。

### 精密仿真与优化服务合同

当前 Node 服务不内嵌 Orekit、Basilisk 或 OR-Tools。可通过下列环境变量连接隔离的计算服务；未配置或上游失败时，系统会明确回退到本地 TLE/假设传感器/有界搜索，不会把回退结果标成精密结果：

- `SATELLITE_VISIBILITY_API_URL`：可见性计算 POST 地址。
- `SATELLITE_VISIBILITY_CAPABILITIES_URL`：能力清单 GET 地址，必须返回 `tianxun.visibility.capabilities/v1`，声明计算引擎、移动 AOI、精度层级和已验证工程约束。台风逐时移动 AOI 必须得到该清单的显式支持。
- `MISSION_OPTIMIZER_API_URL`：优化器 POST 地址，接收 `tianxun.optimizer.problem-set/v1`，OR-Tools 服务返回 `tianxun.optimizer.selection/v1` 与机会引用。返回选择会再次经过本系统的人工规则、重访次数和同星冲突校验。
- `MISSION_SERVICE_TOKEN`：上述内部计算服务共用的可选 Bearer Token。生产环境只允许 HTTPS，HTTP 仅限回环地址。

## VPS 后台与飞书通知

`vps/scripts/install.sh` 把采集引擎、SQLite 状态库、独立两分钟采集器和 Hermes 通知器部署到回环地址；是否开放只读网页由独立 Nginx 配置决定。安装器生成管理、操作员和执行器三种独立令牌。配置 Hermes 与飞书后，再手工运行一次 `systemctl start tianxun-notifier.service`；验证成功后才启用五分钟通知定时器：

```bash
systemctl enable --now tianxun-notifier.timer
```

安装器会同时启用独立灾害采集、每日 TLE 更新和每日 SQLite 在线备份。备份默认保留 14 天并带 SHA-256 校验，位置为 `/var/backups/tianxun`；`vps/scripts/restore.sh` 提供受限路径、停写和完整性校验的恢复流程。`vps/scripts/healthcheck.sh` 核对 readiness、Hermes、各定时器、通知死信和最近备份。
